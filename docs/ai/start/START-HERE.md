# START-HERE — Codex Chat Startup Guide

Use this file at the beginning of each new repository task.

## Startup read order

Read only:

1. `AGENTS.md`
2. `docs/ai/start/START-HERE.md`
3. `docs/ai/start/CONTEXT-MAP.md`

Then identify the documentation owner and read only the files selected by the context map.

## Owner selection

- reusable governance: `docs/ai/AI-DOCS-INDEX.md`
- repository-wide or cross-component work: `docs/project/PROJECT-DOCS-INDEX.md`, then the project profile declared there
- owner discovery: the repository's owner-discovery index
- owner-local work: the selected owner's local router, entry, manifest, and governance profile

Follow the selected manifest's declared entry, profile, and indexes. An uncreated path is never authoritative.

Classify ownership from content, scope, audience, source of truth, consumers, and dependencies. Do not classify from a filename or folder alone.

## Optional structure and maintenance context

Read only when needed:

- `docs/ai/start/AI-STRUCTURE-GUIDE.md`
- `docs/ai/STRUCTURE-GUIDE.md`
- `docs/ai/rules/DOCUMENT-MAINTENANCE-RULES.md`

## Default read budget

Before the first context summary, load the mandatory startup files, the selected owner entry/profile/manifest, and the current Pack. Load Canonical, Guide, Run, Review, Decision, or reference files only when the task requires them.

Do not read all Packs, Runs, Reviews, or source references at startup.

## Required startup output

Report:

1. current branch and working-tree status;
2. selected owner scope;
3. applicable Pack and source-of-truth files;
4. main execution rules and risks;
5. context deferred until needed.

Then follow the Pack's approval gate.
